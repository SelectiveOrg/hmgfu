# Project ID: hmg-fu

## Goal

Build a **complete, working prototype of the HMG-Fu memory algorithm** — a relational,
self-organising memory layer for AI agents based on two source documents by Helencio H. Ferreira:

1. *Algoritmo de Memória HMG-Fu* (33 pp) — the formal theory: memory points, Fu edges,
   ontological density ρ, coupling κ, relation type Ω, energy propagation Φ, retrieval Ψ,
   decay Δ, compression/promotion Λ, dream loop, wormholes, contradictions.
2. *HMG-01 Vision* (3 pp) — the product vision: hexagonal geometric memory, macro→micro zoom
   navigation, emotional indexing, explainability ("see where the AI walked to answer"),
   "the AI that always remembers".

Memory is not a passive database — it is a **living relational field**: the value lives in the
*interval between points* (Fu), not in the points themselves.

## Scope

### In Scope
- Theory analysis + polish document (`docs/THEORY.md`) — corrections, normalisations, ambiguity resolutions.
- Core library (`hmgfu/`): hex grid math, Fu math (ρ, κ, Ω, F, activation score, decay), SQLite store, in-memory graph.
- Full ingestion pipeline: sensitize → embed → density → hex placement → FuEdges → energy propagation → macro update.
- Hybrid retrieval: semantic + entity + goal + recency + dense-identity + wormhole channels → activation scoring → Fu expansion → token-budgeted LLM injection.
- Dream loop: macro consolidation, wormhole creation, contradiction detection, decay (dormancy, never hard-delete), promotion, insights.
- Master cycle: chat with `gemma4:12b` where every turn retrieves, injects, responds, ingests, reinforces.
- FastAPI backend + Cowork browser UI: resizable canvas, live relational hex field, original
  animated macro→micro compression mode, activation trace, layer counts, and persistent widgets.
- CLI chat for terminal use.
- Unit tests (deterministic, no Ollama needed) + live smoke test (real Ollama).

### In Scope — v2 agentic layer (added 2026-07-03, from PA3 architecture analysis)
Port the *concepts* of PriorAgent (see `docs/PA3_LESSONS.md`) — better and simpler:
- **Tools/skills as HMG points**: tool & skill selection IS memory retrieval (replaces PA3's dual
  gallery + category classifier + skill-doc machinery with one native mechanism).
- **Agentic turn loop** on gemma4:12b with tool calling + PA3-proven guards (failure classification,
  2-strike tool block, stuck-loop detection, forced finalization).
- **Learning loop**: turn grader (nano or main model — runtime-selectable), usefulness EMA feeding
  density, correction→supersession, playbook/pattern extraction from successful multi-tool turns.
- **Multi-provider selector**: ollama + OpenAI-compatible + Anthropic behind one Provider interface,
  per-role routing (chat/nano/dream/grader/embed) switchable at runtime via settings API.
- **Self skill creation**: `create_skill` tool — AST-validated `skills/*.py` hot-registered and
  ingested as HMG points.
- **APIs for the coming frontend**: memory search, memory timeline, tool gallery, skill gallery,
  providers/settings, grader card, import status.
- **PA3 memory import** (read-only source): LIVE fact statements + curated node kinds re-embedded
  into this HMG-Fu graph as the test corpus.
- **Connectors**: registry + encrypted credential vault + status API, MCP connections, and Google's
  two-stage remote OAuth through the local `gog` CLI skill.

### Out of Scope
- PostgreSQL/pgvector, Redis, Celery (theory doc §28 suggests them for production — prototype uses SQLite + APScheduler-free periodic trigger).
- Multi-user auth, deployment, packaging for distribution.
- Modifying PriorAgent in any way (its DB/env are read-only sources; the projects stay independent).
- Write-side probes against the PRODUCTION `hmgfu.db` (benches/tests use clones; a live replay may only restate the user's real values — Phase 69 incident: a test sentence changed the real home city and had to be rolled back).
- Fine-tuning or training models; a general hosted OAuth broker (Google uses local `gog` remote OAuth).
- Voice/companion layer (PA3 area 09) — not in this prototype.
